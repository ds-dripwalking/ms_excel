# Подробный план разработки MVP «Комбайн»

Выгрузка заказов и прайс-листов из МойСклад в XLSX, CSV, JSON, YML с доставкой в файлы, Яндекс.Диск, Облако Mail.ru, Google Drive, по секретной ссылке и Email.

---

## 1. Цель MVP

Нужно разработать приложение для маркетплейса МойСклад, которое:

1. Читает данные из МойСклад через JSON API 1.2:
   - заказы покупателей;
   - товары, цены, остатки.

2. Позволяет пользователю настроить профиль выгрузки:
   - модуль: «Заказы» или «Прайс-лист»;
   - поля и их порядок;
   - фильтры;
   - формат файла;
   - канал доставки;
   - расписание.

3. Генерирует файлы:
   - XLSX;
   - CSV;
   - JSON;
   - YML.

4. Доставляет файл:
   - в Яндекс.Диск;
   - в Облако Mail.ru;
   - в Google Drive;
   - по секретной ссылке;
   - на Email.

5. Имеет базовую служебную механику:
   - ручной запуск;
   - кнопка «Тест»;
   - журнал выполнений;
   - уведомления об успехе и ошибках;
   - корректная работа с подпиской и триалом;
   - обработка установки, удаления, приостановки и возобновления приложения.

## 2. Итоговый технологический стек

### 2.1. Выбор бэкенда: FastAPI или NestJS

Для MVP рекомендуется использовать **FastAPI**.

| Критерий | FastAPI | NestJS |
|---|---:|---:|
| Скорость разработки MVP | Высокая | Средняя |
| Удобство для интеграций и фоновых задач | Высокое | Высокое |
| Экспорт файлов, XML/YML, CSV, Excel | Очень удобно в Python | Удобно, но больше кода |
| Работа с WebDAV, OAuth, HTTP-клиентами | Удобно | Удобно |
| Валидация Vendor API и конфигураций | Pydantic | class-validator / DTO |
| Очередь задач | Celery / Redis | BullMQ / Redis |
| Если команда сильна в TypeScript | Не всегда | Хорошо |
| Итог для данного MVP | **Рекомендуется** | Допустим, если команда полностью TypeScript |

**Почему FastAPI лучше для данного MVP:**

1. Много работы с выгрузками:
   - CSV;
   - XLSX;
   - JSON;
   - YML/XML;
   - кодировки;
   - большие таблицы.

   В Python это делается быстрее и проще.

2. Нужны фоновые задачи и планировщик:
   - Celery;
   - Redis;
   - Celery Beat.

3. Нужны интеграции:
   - МойСклад JSON API;
   - МойСклад Vendor API;
   - Яндекс.Диск;
   - Облако Mail.ru WebDAV;
   - Google Drive;
   - SMTP;
   - Telegram.

4. FastAPI дает хорошую валидацию через Pydantic и удобную генерацию OpenAPI.

**Основной выбор:**

```text
Backend: FastAPI + Python 3.12
Queue/Worker: Celery + Redis
Database: PostgreSQL 16
ORM: SQLAlchemy 2.0 + Alembic
Frontend: Vue 3 + Vite + TypeScript
Infra: Docker Compose
```

Если команда разработки полностью и уверенно работает на TypeScript, можно использовать альтернативный вариант:

```text
Backend: NestJS + TypeScript
Queue: BullMQ + Redis
Database: PostgreSQL
ORM: Prisma или TypeORM
Frontend: Vue 3
```

Но далее план описывается под **FastAPI**, так как это более практичный выбор для экспортного «комбайна».

## 5. База данных

Используем PostgreSQL 16.

Основные таблицы:

### 5.1. `accounts`

Аккаунт МойСклад, который установил приложение.

```sql
CREATE TABLE accounts (
    id UUID PRIMARY KEY,
    account_name VARCHAR(255),
    app_uid VARCHAR(255),
    access_token_encrypted TEXT,
    subscription_tier VARCHAR(20), -- trial | lite | professional
    is_trial BOOLEAN DEFAULT FALSE,
    trial_end_date TIMESTAMPTZ,
    paid_end_date TIMESTAMPTZ,
    status VARCHAR(30), -- activated | suspended | deleted_pending
    settings JSONB DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 5.2. `export_profiles`

Профили выгрузки.

```sql
CREATE TABLE export_profiles (
    id UUID PRIMARY KEY,
    account_id UUID REFERENCES accounts(id),
    name VARCHAR(255),
    module VARCHAR(20), -- orders | pricelist
    fields_config JSONB,
    filters JSONB,
    format_config JSONB,
    channel_config JSONB,
    schedule_config JSONB,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 5.3. `cloud_credentials`

Токены и секреты облачных дисков.

```sql
CREATE TABLE cloud_credentials (
    id UUID PRIMARY KEY,
    account_id UUID REFERENCES accounts(id),
    provider VARCHAR(30), -- yandex | mailru | google | email | telegram
    credential_type VARCHAR(30), -- oauth | webdav | smtp | bot
    encrypted_payload TEXT,
    expires_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 5.4. `export_jobs`

Журнал выполнений.

```sql
CREATE TABLE export_jobs (
    id UUID PRIMARY KEY,
    account_id UUID REFERENCES accounts(id),
    profile_id UUID REFERENCES export_profiles(id),
    status VARCHAR(20), -- pending | running | success | failed | canceled
    run_type VARCHAR(20), -- manual | schedule | test
    rows_count INTEGER,
    file_size BIGINT,
    file_name VARCHAR(255),
    channel VARCHAR(30),
    error_code VARCHAR(50),
    error_message TEXT,
    started_at TIMESTAMPTZ,
    completed_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 5.5. `job_events`

Детальные события по задаче.

```sql
CREATE TABLE job_events (
    id UUID PRIMARY KEY,
    job_id UUID REFERENCES export_jobs(id),
    step VARCHAR(100),
    level VARCHAR(20), -- info | warning | error

    payload JSONB,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 5.6. `vendor_requests`

Идемпотентность для Vendor API.

```sql
CREATE TABLE vendor_requests (
    id UUID PRIMARY KEY,
    jti VARCHAR(255) UNIQUE,
    request_id VARCHAR(255),

    operation VARCHAR(30), -- activate | deactivate
```

### 5.7. `dictionary_cache`

Кэш справочников МойСклад.

## 6. Основные API-эндпоинты

### 6.1. Vendor API от МойСклад

Эти эндпоинты вызывает МойСклад.

#### Активация

```text
PUT /api/moysklad/vendor/1.0/apps/{appId}/{accountId}
```

В теле приходят:

- `appUid`;
- `accountName`;
- `cause`;
- `access`;
- `subscription`.

Возможные `cause`:

- `Install`;
- `Resume`;
- `TariffChanged`;
- `Autoprolongation`.

Ответ:

```json
{
  "status": "Activated | Activating | SettingsRequired"
}
```

#### Деактивация

```text
DELETE /api/moysklad/vendor/1.0/apps/{appId}/{accountId}
```

Возможные `cause`:

- `Uninstall`;
- `Suspend`.

Ответ: пустой, только HTTP-статус.

## Этап 3. Реализация Vendor API

### Цель

При повторном запросе:

- не создавать дубли;
- возвращать уже корректный результат;
- логировать `X_Lognex_RequestId`.

#### 3.3. Активация

Эндпоинт:

```text
PUT /api/moysklad/vendor/1.0/apps/{appId}/{accountId}
```

Обработка `cause`:

##### Install

Первая установка.

Действия:

1. Создать аккаунт.
2. Сохранить зашифрованный токен JSON API.
3. Сохранить подписку.
4. Остановить задачи, если были.
5. Вернуть:

```json
{
  "status": "SettingsRequired"
}
```

Пользователь должен настроить первый профиль.

##### Resume

Возобновление после приостановки.

Действия:

1. Обновить токен.
2. Восстановить настройки.
3. Проверить подписку.
4. Запустить планировщик.
5. Вернуть:

```json
{
  "status": "Activated"
}
```

##### TariffChanged

Смена тарифа.

Действия:

1. Обновить тариф.
2. Применить ограничения:
   - Lite — один модуль, до 3 профилей;
   - Professional — без ограничений.
3. Вернуть:

```json
{
  "status": "Activated"
}
```

##### Autoprolongation

Автопродление.

Действия:

1. Обновить `paid_end_date`.
2. Разблокировать задачи, если были заблокированы.
3. Вернуть:

```json
{
  "status": "Activated"
}
```

#### 3.4. Деактивация

Эндпоинт:

```text
DELETE /api/moysklad/vendor/1.0/apps/{appId}/{accountId}
```

##### Suspend

Приостановка из-за неоплаты.

Действия:

1. Остановить планировщик.
2. Запретить ручной запуск.
3. Сохранить профили.
4. Сохранить журнал.
5. Не удалять токены облаков сразу.
6. Поставить статус `suspended`.

##### Uninstall

Удаление.

Действия:

1. Остановить задачи.
2. Пометить аккаунт как `deleted_pending`.
3. Запустить очистку через grace-период, например 30 дней.
4. После grace-периода удалить:
   - токены;
   - секреты;
   - настройки;
   - файлы временных выгрузок.

### Критерий приемки

## 9. Технические требования к надежности

### 9.1. Rate limit

Для МойСклад:

```text
не более 3-5 запросов в секунду на аккаунт
```

Использовать:

- локальный лимитер в клиенте;
- общий лимитер через Redis;
- backoff при 429.

### 9.2. Повторные попытки

Повторять при:

- 429;
- 5xx;
- сетевых ошибках;
- таймаутах.

Не повторять автоматически при:

- 401 без попытки обновления токена;
- 403;
- 404;
- ошибках валидации;
- переполнении диска, если требуется действие пользователя.

### 9.3. Таймауты

```text
Подключение: 10 секунд
Чтение: 60-300 секунд в зависимости от операции
Загрузка файла: до 10 минут для больших файлов
```

### 9.4. Большие данные

- чанки по 1000 записей;
- потоковая генерация CSV/JSON/YML;
- ограничение одновременных задач на аккаунт;
- временные файлы на диске, а не в памяти;
- при превышении лимита строк — делить файл.

## 10. Безопасность

### 10.1. Данные

- Не хранить выгруженные файлы дольше необходимого.
- Удалять временные файлы после доставки.
- Не хранить персональные данные в логах.
- Маскировать телефоны и email.

### 10.2. Токены

- Шифрование at rest.
- Ключ вне базы.
- Ротация ключа в будущем.
- Удаление токенов после удаления аккаунта.

### 10.3. Доступ

- Только права просмотра в МойСклад.
- Никаких админских прав.
- Проверка контекста пользователя.
- Разделение данных по `account_id`.

### 10.4. Инфраструктура

- HTTPS везде.
- SSH-ключи.
- БД и Redis не наружу.
- Фаервол.
- Минимальные привилегии контейнеров.

## 16. Риски и как их снижать

### 16.1. Mail.ru WebDAV нестабилен

**Риск:** ошибки доставки.

**Решение:**
- детальное логирование;
- retry;
- понятные ошибки;
- Яндекс.Диск как флагманский канал.

---

### 16.2. Google OAuth верификация

**Риск:** задержка с публикацией.

**Решение:**
- заранее подать на верификацию;
- при необходимости временно сделать Google-канал по флагу;
- основной акцент на российские облака.

---

### 16.3. Большие объемы данных

**Риск:** память, таймауты.

**Решение:**
- чанки;
- streaming;
- временные файлы;
- лимиты на аккаунт;
- деление больших файлов.

---

### 16.4. Повторные запросы от МойСклад

**Риск:** дублирование установок и состояний.

**Решение:**
- идемпотентность;
- `jti`;
- `X_Lognex_RequestId`;
- идемпотентные операции.

---

### 16.5. Низкая конверсия триала

**Риск:** пользователи не доходят до первого экспорта.

**Решение:**
- онбординг;
- пресеты;
- кнопка «Тест»;
- цель: первый успешный экспорт за 24 часа.
