## 1. Стратегия и позиционирование

### 1.1 Продуктовая логика

Чат-боты — «всегда включенный» канал доставки выгрузок и уведомлений, который работает там, где клиент уже есть (в мессенджере). В отличие от Email: мгновенные реакции, кнопки, интерактив.

- **Telegram** — базовый канал уведомлений и доставки (P0 — уведомления, P1 — файлы/кнопки; паритет с конкурентами).
- **MAX** — **стратегическое УТП наравне с российскими облаками**: первое приложение для МойСклад с ботом в MAX, закрывающее экосистему VK (Яндекс.Диск + Облако Mail.ru + MAX = полный охват российского цифрового стека).

### 1.2 Конкурентное преимущество MAX

- Ни один из 3 конкурентов не имеет интеграции с MAX.
- MAX продвигается VK как корпоративный мессенджер РФ (импортозамещение Telegram/WhatsApp).
- Файлы до 4 ГБ (против 50 МБ в Telegram) — критично для больших прайс-листов с изображениями.
- Кнопка `request_contact` с hash-верификацией — безопасная привязка пользователя без SMS/email.
- Бот в MAX = точка присутствия в экосистеме VK, где у клиентов уже есть рабочие чаты.

### 1.3 Маркетинговый оффер

«Яндекс.Диск + Облако Mail.ru + MAX = полный российский стек для вашего МойСклад» — импортозамещение на трёх уровнях: хранение, диски/почта, корпоративный мессенджер.

## 2. Telegram Bot API

### 2.1 Что нужно для старта

- Создать бота через @BotFather → получить `bot_token`.
- Настроить Webhook на нашем домене (HTTPS, валидный сертификат). Long Polling — только для разработки.
- Хранить per-client токены зашифрованными.

### 2.2 Ключевые эндпоинты

База: `https://api.telegram.org/bot<token>/`

| Операция | Метод |
|---|---|
| Отправка текста | `POST /sendMessage` |
| Отправка файла | `POST /sendDocument` |
| Отправка изображения | `POST /sendPhoto` |
| Редактирование сообщения | `POST /editMessageText` |
| Удаление сообщения | `POST /deleteMessage` |
| Установка вебхука | `POST /setWebhook` |
| Получение обновлений | `GET /getUpdates` (только dev) |
| Информация о боте | `GET /getMe` |
| Установка команд меню | `POST /setMyCommands` |

### 2.3 Авторизация

Токен передаётся в URL: `https://api.telegram.org/bot<TOKEN>/<method>`.

### 2.4 Отправка файла

Через multipart/form-data (до 50 МБ):

```bash
curl -X POST https://api.telegram.org/bot<TOKEN>/sendDocument \
  -F chat_id=123456789 \
  -F document=@report.xlsx \
  -F caption="Отчет за 01.09.2026"
```

Через file_id (до 20 МБ, без повторной загрузки):

```json
{
  "chat_id": 123456789,
  "document": {"file_id": "BQACAgIAAxkDAAJ..."},
  "caption": "Отчет за 01.09.2026",
  "parse_mode": "HTML"
}
```

### 2.5 Форматирование и клавиатуры

- MarkdownV2 или HTML (`parse_mode`).
- Inline-кнопки: `reply_markup: {"inline_keyboard": [[{"text": "...", "callback_data": "..."}]]}`.

### 2.6 Ограничения

- Файлы: до 50 МБ (upload), до 20 МБ (file_id).
- Rate limits: 30 сообщений/сек на бота, 1 сообщение/сек в один чат.
- Production — только Webhook.

## 3. MAX Bot API (VK)

### 3.1 Что нужно для старта

1. Подключиться к платформе MAX для партнёров (юрлицо / ИП / самозанятый, резидент РФ).
2. Создать и верифицировать профиль организации.
3. Создать чат-бота: логотип (500×500 px, ≤5 МБ), название (1–59 символов), описание (≤200 символов). Ник генерируется автоматически: `id<ИНН>_bot` (юрлица/ИП) или `se<orgid>_bot` (самозанятые).
4. Пройти модерацию (до 48 рабочих часов).
5. Получить `access_token`: Чат-боты → Перейти → Расширенные настройки (или команда «Получить токен» в боте «MAX для бизнеса»).

Лимит ботов на профиль: юрлицо/ИП — 5, самозанятый — 2.

### 3.2 Ключевые эндпоинты

База: `https://platform-api2.max.ru/` (вместо устаревшего `platform-api.max.ru`; добавить сертификат Минцифры в доверенные).

| Операция | Метод | Примечание |
|---|---|---|
| Отправка сообщения | `POST /messages` | диалог / чат / канал, текст + вложения |
| Редактирование | `PUT /messages/{messageId}` | |
| Загрузка медиа | `POST /uploads?type={type}` | возвращает `url` и `token` |
| Подписка на события | `POST /subscriptions` | Webhook (production) |
| Список подписок | `GET /subscriptions` | |
| Отписка | `DELETE /subscriptions` | |
| Обновления | `GET /updates` | Long Polling, только dev |
| Информация о боте | `GET /me` | |
| Команды бота | `PATCH /me/commands` | |

### 3.3 Авторизация

Заголовок `Authorization: <token>`. Передача токена через query-параметры больше не поддерживается.

### 3.4 Отправка сообщения

```json
POST /messages
{
  "chat_id": 123456789,
  "text": "Отчет за 01.09.2026",
  "format": "markdown",
  "attachments": [
    { "type": "file", "payload": { "token": "..." } }
  ]
}
```

- `text` — до 4000 символов; `format`: `markdown` или `html`.
- `user_id` — для диалога, `chat_id` — для чата/канала.
- `chat_id` получается из событий Webhook (`bot_started`, `bot_added`).

### 3.5 Загрузка файла (двухэтапный процесс)

Шаг 1 — получить URL и токен:

```bash
curl -X POST "https://platform-api2.max.ru/uploads?type=file" \
  -H "Authorization: {access_token}"
→ { "url": "https://...", "token": "..." }
```

Шаг 2 — загрузить файл на полученный URL (multipart или resumable):

```bash
curl -i -X POST \
  -H "Content-Type: multipart/form-data" \
  -F "data=@report.xlsx" "{url}"
```

Шаг 3 — отправить сообщение с `attachments[].payload.token`.

### 3.6 Типы вложений и лимиты

| Тип | Форматы | Лимит |
|---|---|---|
| `image` | JPG, JPEG, PNG, GIF, TIFF, BMP, HEIC | 50 МБ и ≤7680×7680 px |
| `video` | MP4, MOV, MKV, WEBM | 250 МБ |
| `audio` | MP3, WAV, M4A | 256 МБ и ≤60 мин |
| `file` | TXT, DOC, PDF и др. | **4 ГБ** |
| `inline_keyboard` | кнопки | до 210 кнопок / 30 рядов / 7 в ряд (3 для link/open_app/geo/contact) |

Комбинации: до 12 вложений (image+video+1 клавиатура); **файл — только 1 и только вместе с клавиатурой** (не с image/video). Для изображений возможна альтернатива токену — прямая `url`.

### 3.7 Inline-клавиатура

```json
{
  "type": "inline_keyboard",
  "payload": {
    "buttons": [
      [
        { "type": "callback", "text": "Запустить снова", "payload": "run_now" },
        { "type": "link", "text": "Скачать файл", "url": "https://..." }
      ]
    ]
  }
}
```

Типы кнопок:
- `callback` — событие `message_callback` на Webhook;
- `link` — открыть URL (≤2048 символов);
- `message` — отправить боту заданный текст;
- `clipboard` — скопировать `payload` в буфер (промокод, реквизиты);
- `request_contact` — запросить номер телефона (с `hash` для верификации: `HMAC-SHA256(access_token, vcf_info)`);
- `request_geo_location` — геолокация;
- `open_app` — мини-приложение.

### 3.8 Webhook (production)

```json
POST /subscriptions
{
  "url": "https://your-domain.com/webhook",
  "update_types": ["bot_started", "message_created", "message_callback"],
  "secret": "your_secret"
}
```

Требования:
- только HTTPS на порту 443 (HTTP и самоподписные сертификаты не поддерживаются с 25.05.2026);
- сертификат от доверенного CA, включая сертификат Минцифры;
- проверка заголовка `X-Max-Bot-Api-Secret` на своём сервере;
- endpoint должен отвечать HTTP 200.

### 3.9 Ограничения

- 2 сообщения/сек в один чат (очередь/задержки на нашей стороне);
- 30 rps на `platform-api2.max.ru`;
- Long Polling — только разработка/тест.

## 4. Единый адаптер чат-ботов

Все мессенджеры реализуют общий интерфейс — профили, планировщик и журнал не знают о конкретном мессенджере:

```
connect(token)            -> session / raise AuthError
test()                    -> bool (кнопка «Проверить подключение»)
send_message(chat_id, text, format="markdown")        -> message_id
send_file(chat_id, stream, filename, caption=None)    -> message_id
send_keyboard(chat_id, text, buttons)                 -> message_id
subscribe_webhook(url, events, secret)                -> ok
```

Единое поведение:
- retry с экспоненциальной задержкой на 429/5xx;
- rate limiting per-chat (Telegram 1 msg/s, MAX 2 msg/s);
- маппинг ошибок в человекочитаемые сообщения журнала (раздел 8);
- таймауты: connect 10 c, send 60 c;
- файлы >50 МБ в Telegram — заменяются ссылкой на облачный диск (в MAX — до 4 ГБ).

## 5. Сценарии использования

### 5.1 Уведомления о задачах (P0)

Успех:

```
✅ Выгрузка завершена
Профиль: Заказы за день
Файл: orders_2026-09-03.xlsx
Строк: 1 247 · Размер: 2,3 МБ · Время: 12 с
```

Ошибка:

```
❌ Ошибка выгрузки
Профиль: Прайс-лист
Причина: диск переполнен (507)
Проверьте свободное место или смените папку
```

### 5.2 Доставка файлов (P1)

- XLSX/CSV/JSON/YML — документом в чат;
- файлы >50 МБ (Telegram) — кнопкой-ссылкой на облачный диск;
- caption с метаданными: дата, профиль, число строк.

### 5.3 Быстрые действия (P1)

Inline-кнопки под сообщением: `[🔄 Запустить снова] [📊 Журнал] [⚙️ Настройки]` (Telegram — callback_data, MAX — `callback`).

### 5.4 Команды (P1)

- `/status` — статус профилей и последних задач;
- `/run <профиль>` — ручной запуск;
- `/help` — справка.
Telegram — через `setMyCommands`; MAX — кнопки типа `message`.

### 5.5 Привязка клиента к боту (P0/P1)

- Telegram: пользователь пишет боту → `chat_id` привязывается к клиенту.
- MAX: кнопка `request_contact` → hash-верификация номера → привязка.

## 6. Безопасность и хранение токенов

- Токены ботов и `chat_id` — зашифрованы at rest (AES-256-GCM), ключ вне БД.
- MAX: обязательная проверка `X-Max-Bot-Api-Secret` на Webhook.
- Токены не попадают в логи.
- При отписке клиента: остановка задач → очистка токенов после grace-периода.

---

## 7. Приоритеты и rollout

**P0 (релиз 1.0):**
- Telegram: уведомления об успехе/ошибке задач.

**P1 (1–2 мес):**
- Telegram: доставка файлов, inline-кнопки, команды;
- MAX: полная интеграция — отправка, файлы (до 4 ГБ), клавиатуры, `request_contact`, Webhook.

**P2 (по тяге клиентов):**
- уведомления о новых заказах (CRM-сценарий);
- сводки/аналитика в боте;
- другие мессенджеры через тот же адаптер (VK Мессенджер, WhatsApp Business).

## 8. Обработка ошибок

| Код / ситуация | Telegram | MAX | Действие |
|---|---|---|---|
| 401 | «Пересоздайте токен в @BotFather» | «Переподключите бота в настройках MAX» | стоп профиля до переподключения |
| 400 | неверный chat_id/формат | неверный chat_id/формат | лог + подсказка |
| 403 | бот заблокирован пользователем | бот не добавлен в чат | подсказка по настройке |
| 404 | chat_id не найден | chat_id не найден | лог + уведомление |
| 413 / 429 | файл велик / rate limit | файл велик / rate limit | ссылка на диск / retry с задержкой |
| 5xx / сетевые | временный сбой | временный сбой | retry с экспоненциальной задержкой |

## 9. Чек-лист перед разработкой

**Telegram:**
- [ ] бот в @BotFather, токен;
- [ ] `sendMessage` / `sendDocument` с файлом >10 МБ;
- [ ] Webhook (HTTPS, валидный сертификат);
- [ ] rate limits (30 msg/s, 1 msg/chat/s).

**MAX:**
- [ ] профиль на платформе MAX (юрлицо/ИП), верификация;
- [ ] создание бота, модерация (до 48 ч), получение `access_token`;
- [ ] `POST /uploads?type=file` → multipart → `POST /messages` с token;
- [ ] inline-клавиатура: `callback`, `link`, `message`;
- [ ] Webhook: HTTPS 443, сертификат (в т.ч. Минцифры), проверка `X-Max-Bot-Api-Secret`;
- [ ] `request_contact` + hash-верификация;
- [ ] rate limits (2 msg/chat/s, 30 rps).

**Общее:**
- [ ] кнопка «Проверить подключение» для каждого мессенджера;
- [ ] онбординг-инструкции (как добавить бота, как получить токен);
- [ ] шаблоны сообщений уведомлений (успех/ошибка).

## 10. Сводная таблица мессенджеров

|---|---|---|
| Приоритет | P0 (уведомления) / P1 (файлы) | P1 — УТП |
