## 1. Ландшафт провайдеров и стратегия

| Провайдер | Тип | Протокол | Аутентификация | Публичная ссылка | Приоритет |
|---|---|---|---|---|---|
| Яндекс.Диск | потребительский диск | REST (+ WebDAV fallback) | OAuth 2.0 | ✅ (PATCH public) | P0 — флагман |
| Облако Mail.ru | потребительский диск (экосистема VK) | WebDAV | логин + пароль приложения | ❌ официально | P0 — УТП |
| Google Drive | потребительский диск | Drive API v3 | OAuth 2.0 | ✅ (permissions) | P0 — паритет |
| VK Cloud | бизнес, object storage | S3 | AccessKey/SecretKey (SigV4) | ✅ (public bucket / presigned) | P1 — через S3-адаптер |
| MTS Cloud | бизнес, object storage | S3 | AccessKey/SecretKey (SigV4) | ✅ (public bucket / presigned) | P1 — через S3-адаптер |
| Yandex Object Storage | бизнес, object storage | S3 | статические ключи Yandex Cloud | ✅ | P1 — через S3-адаптер |
| СберДиск | потребительский диск | публичного API нет | — | — | мониторинг (P2) |

**Стратегия:**
- Не строить интеграцию под каждого S3-провайдера — один универсальный **S3-адаптер** с настраиваемым endpoint закрывает VK Cloud, MTS Cloud, Yandex Object Storage, Selectel и любой AWS-совместимый S3.
- Потребительские диски (Яндекс, Mail.ru, Google) — точечные адаптеры: именно они дают УТП «российские облака» для малого бизнеса.
- Яндекс.Диск — флагман: единственный потребительский диск с полноценным REST API и публичными ссылками (сценарий «YML → публичная ссылка → Яндекс.Маркет»).

## 2. Единый адаптер хранилищ (контракт)

Все адаптеры реализуют общий интерфейс —上层 (профили, планировщик, журнал) не знают о конкретном провайдере:

```
connect(credentials)      -> session / raise AuthError
test()                    -> bool (кнопка «Проверить подключение»)
ensure_folder(path)       -> создать папку (идемпотентно)
upload(stream, path, overwrite=true) -> remote_meta   (streaming, без загрузки целого файла в RAM)
publish(path)             -> public_url | None        (если провайдер поддерживает)
list(path)                -> [items]
delete(path)
```

**Поведение, единое для всех адаптеров:**
- overwrite-семантика: постоянный путь файла (для публичных ссылок) либо имя с датой по шаблону (для истории);
- streaming upload для файлов > 100 МБ;
- retry с экспоненциальной задержкой на сетевые ошибки и 429/5xx;
- маппинг ошибок провайдера в человекочитаемые сообщения журнала (раздел 9);
- таймауты по умолчанию: connect 10 c, read/write 300 c (настраиваемые).

## 3. Яндекс.Диск

### 3.1 Что нужно для старта

1. Зарегистрировать OAuth-приложение на `https://oauth.yandex.ru/`:
   - redirect URI на нашем домене;
   - скоупы: `disk:read`, `disk:write` (либо `disk:app_folder` для режима «папка приложения» — решает продуктовая политика; сверить актуальный список скоупов в документации).
2. Хранить `client_id` / `client_secret`; per-user токены — зашифрованными.

### 3.2 OAuth-флоу

```
GET  https://oauth.yandex.ru/authorize?response_type=code&client_id=...&redirect_uri=...
POST https://oauth.yandex.ru/token   (code → access_token + refresh_token)
refresh: grant_type=refresh_token
```

### 3.3 REST API

База: `https://cloud-api.yandex.net/v1/disk/`

| Операция | Метод и путь |
|---|---|
| Информация о диске | `GET /v1/disk/` |
| Метаданные / список | `GET /v1/disk/resources?path=&limit=&offset=` |
| Ссылка на загрузку | `GET /v1/disk/resources/upload?path=&overwrite=true` → `{href, method}` → затем `PUT href` (тело файла) |
| Ссылка на скачивание | `GET /v1/disk/resources/download?path=` |
| Публикация | `PATCH /v1/disk/resources?path=` тело `{"public": true}` → в ответе `public_url` |
| Снятие публикации | `PATCH` тело `{"public": false}` |
| Удаление | `DELETE /v1/disk/resources?path=&permanently=` |
| Копирование / перемещение | `POST /v1/disk/resources/copy` / `.../move?from=&path=` |
| Создание папки | `POST /v1/disk/disk/resources?path=` (сверить путь с актуальной документацией) |
| Статус асинхронной операции | `GET /v1/disk/operations/{operation_id}` |

**Публичная ссылка:** формат `https://disk.yandex.ru/d/...` — постоянная, пока файл опубликован. Ключевой сценарий: overwrite одного файла + публикация → стабильный URL для Яндекс.Маркета.

### 3.4 WebDAV (fallback / простой режим)

- URL: `https://webdav.yandex.ru`
- Auth: Basic, логин + **пароль приложения** (создается в Яндекс ID).
- Методы: PROPFIND, PUT, GET, MKCOL, DELETE, MOVE, COPY.
- Использовать как запасной вариант и для быстрой проверки связности.

### 3.5 Ограничения (сверить)

- Размер файла ограничен квотой диска пользователя (10 ГБ бесплатно, платные тарифы больше).
- Rate limits: ориентироваться на ~1 rps на пользователя, обрабатывать 429.

## 4. Облако Mail.ru

> Потребительское облако VK (cloud.mail.ru). Не путать с VK Cloud (бизнес, S3 — раздел 6).

### 4.1 Что нужно для старта

- Регистрация разработчика **не требуется**: пользователь сам дает реквизиты.
- От пользователя: e-mail (или телефон) + **пароль приложения** (создается в настройках профиля при включенной 2FA; обычная связка логин/пароль работает только без 2FA).
- Наша сторона: WebDAV-клиент, зашифрованное хранение реквизитов, инструкция «как создать пароль приложения» в онбординге.

### 4.2 WebDAV

- URL: `https://webdav.cloud.mail.ru`
- Auth: Basic (логин + пароль приложения).
- Методы: `OPTIONS`, `PROPFIND` (список), `PUT` (загрузка, overwrite по умолчанию), `GET`, `MKCOL` (папка), `DELETE`, `MOVE`, `COPY`.

### 4.3 Публичные ссылки — ограничение

- Через WebDAV **официально не создаются**.
- Продуктовое решение (P0): overwrite файла по постоянному пути; клиент при необходимости расшаривает папку вручную в веб-UI; в журнале показываем путь файла.
- P1 (исследование): неофициальный HTTP API share (`/api/v2/.../share`) — нестабилен, в SLA не включаем.

### 4.4 Ограничения (сверить)

- Лимит размера файла при загрузке через WebDAV; квота диска пользователя.
- Ошибка переполнения квоты приходит как `507 Insufficient Storage` — маппим в понятное сообщение.

## 5. Google Drive

### 5.1 Что нужно для старта

- Проект в Google Cloud Console, OAuth consent screen, включить Drive API v3.
- Скоуп: `https://www.googleapis.com/auth/drive.file` (минимально необходимый: только файлы, созданные приложением).

### 5.2 Ключевые операции

| Операция | Метод |
|---|---|
| Загрузка | `POST https://www.googleapis.com/upload/drive/v3/files?uploadType=resumable` (multipart для малых) |
| Перезапись (overwrite) | поиск файла по name/appProperties → `PATCH /drive/v3/files/{id}?uploadType=media` |
| Публичная ссылка | `POST /drive/v3/files/{id}/permissions` `{role: reader, type: anyone}` → `https://drive.google.com/file/d/{id}/view` |
| Список | `GET /drive/v3/files?q=...` |
| Папка | create с `mimeType: application/vnd.google-apps.folder` |

## 6. S3-совместимые хранилища (один адаптер — много провайдеров)

### 6.1 Общая модель

- Auth: AccessKey / SecretKey, подпись AWS Signature V4 (service = `s3`).
- Операции: `PUT object` (streaming), `GET`, `HEAD`, `DELETE`, `LIST objects v2`, presigned URL.
- Публичный доступ: bucket policy `public-read` → постоянный URL объекта; либо presigned URL с TTL (для временных ссылок на выгрузку).
- Overwrite: `PUT` по тому же key — по умолчанию.
- От клиента требуется: endpoint, bucket, AccessKey, SecretKey (создаются в консоли провайдера).

### 6.2 Провайдеры

| Провайдер | Endpoint (сверить) | Публичный URL объекта | Примечание |
|---|---|---|---|
| VK Cloud | `https://s3.vkcloudstorage.ru` | `https://<bucket>.s3.vkcloudstorage.ru/<key>` | регион для SigV4 уточнить в документации |
| MTS Cloud | `https://s3.mts-cloud.ru` | `https://<bucket>.s3.mts-cloud.ru/<key>` | ключи из консоли MTS Cloud |
| Yandex Object Storage | `https://storage.yandexcloud.net` | `https://storage.yandexcloud.net/<bucket>/<key>` | статические ключи через Yandex Cloud IAM |
| Любой AWS-совместимый | настраивается | по endpoint | Selectel, on-premise MinIO и т.п. |

### 6.3 Что это дает продукту

- Корпоративный сегмент («своя инфраструктура, 152-ФЗ») без отдельных интеграций.
- Настройка в UI: «S3-хранилище» с пресетами провайдеров (endpoint подставляется) + ручной режим.

## 7. Безопасность и хранение реквизитов

- OAuth (Яндекс, Google): access + refresh токены, автопродление; при 401 после refresh — просьба переподключить аккаунт.
- Секреты (пароли приложений Mail.ru, S3-ключи): шифрование AES-256-GCM at rest, ключ вне БД (env/KMS).
- Кнопка «Проверить подключение» при сохранении реквизитов (test()).
- Реквизиты и токены не попадают в логи; в логах — только маска (тип провайдера + последние 4 символа key id).
- При отписке клиента: остановка задач → очистка реквизитов после grace-периода.

## 8. Приоритеты

- **P0:** Яндекс.Диск (REST + публичные ссылки), Облако Mail.ru (WebDAV), Google Drive.
- **P1:** универсальный S3-адаптер → VK Cloud, MTS Cloud, Yandex Object Storage, произвольный S3.
- **P2 / мониторинг:** СберДиск (публичного API нет — следить за появлением), Dropbox (низкая релевантность для РФ).

## 9. Обработка ошибок хранилищ

| Код / ситуация | Сообщение в журнале | Действие |
|---|---|---|
| 401 Unauthorized | «Проверьте реквизиты / переподключите аккаунт» | refresh / стоп профиля до переподключения |
| 403 Forbidden | «Нет прав на запись в папку» | подсказка по настройке прав |
| 404 | «Папка не найдена» | авто-ensure_folder, повтор |
| 409 Conflict | «Конфликт имени/папки» | ensure_folder, повтор |
| 413 / 507 | «Файл слишком большой / диск переполнен» | понятная ошибка, уведомление |
| 429 | rate limit | backoff + retry |
| 5xx / сетевые | временный сбой | retry с экспоненциальной задержкой |
