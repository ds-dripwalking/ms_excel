## 1. Резюме

**Продукт** — одно расширение-«комбайн» для МойСклад: экспорт заказов покупателей и прайс-листов (товары/цены/остатки) в форматы XLSX, CSV, JSON, YML с доставкой в облачные диски: Яндекс.Диск, Облако Mail.ru, Google Drive, а также файл-ссылка и Email.

**Дифференциаторы** (в порядке силы):
- **Российские облака** — Яндекс.Диск и Облако Mail.ru нет ни у одного конкурента. Импортзамещение, 152-ФЗ (в заказах — персональные данные клиентов), санкционный риск Google.
- **2-в-1** — одно приложение заменяет две подписки конкурентов (2000–2250 ₽/мес суммарно).
- **Экспорт включён в цену** — без доплат до 1 990 ₽ (как у ЖивойОтчёт).
- **Данные на стороне клиента** — файлы лежат в облаке клиента, а не на сервере вендора.
- **Права «только просмотр»** — контраст с админ-правами Склад24.
- **Цена** — Lite 590 ₽ (дешевле любого конкурента), Pro 990 ₽ (дешевле двух чужих подписок).

**Рынок:** 4 релевантных решения конкурентов, 1300+ установок (оценка платящих ~1500), цены 990–1990 ₽/мес. Платежеспособный спрос доказан.

## 2. Рынок, конкуренты, дыры

### 2.1 Сводка конкурентов

|---|---------|--------|-----------|-------|------|

### 2.2 Базовая линия рынка (пересечение — обязательно иметь)
XLSX/CSV, Google Таблицы, конструктор полей, фильтры, расписание, пробный период, цена ~1000 ₽/мес.

### 2.3 Уникальное конкурентов (что парировать)
- **Склад24:** пресеты маркетплейсов (Avito, drom, Tiu, Юла, загрузка на baza.drom.ru), Liquid-шаблоны, остатки комплектов, изображения, realtime-синк 10+ сущностей в Google Sheets, Data Studio. *Слабость: права администратора.*
- **ЭР (файл):** постоянная секретная ссылка, widest-БД (Oracle, PostgreSQL, MS SQL), YML/JSON по товарам, модификации.
- **ЭР (заказы):** HTML-отчеты, «один заказ = одна строка», умный интервал, фильтры по статусам/сумме, несколько профилей, журнал задач, кнопка «Тест».
- **ЖивойОтчёт:** интерактивная таблица с группировками и фильтрами на лету без повторных запросов к API; макеты (до 5 / без лимита); сохранение результата на 24 ч; экспорт XLSX/PDF **загейтен в тариф 1 990 ₽**; в роадмапе — отчёты по расписанию, свои шаблоны экспорта. *Слабость: только просмотр, нет доставки, нет облачных дисков, только заказы/отгрузки/счета.*

### 2.4 Дыры рынка (наши возможности)
- **Нет облачных дисков вообще** — только Google Таблицы, FTP, БД, почта.
- **Нет российской инфраструктуры** (152-ФЗ, импортозамещение, корпоративные запреты Google).
- **Нет 2-в-1** — за заказы и прайсы платят дважды.
- **Сценарий «YML на Яндекс.Диске → публичная ссылка → Яндекс.Маркет»** не закрыт никем.
- **Экспорт гейтится доплатой** — у ЖивойОтчёта XLSX/PDF только в топ-тарифе 1 990 ₽; у нас экспорт входит в базовый тариф.
- **Интерактивный предпросмотр** выгрузки до отправки — ни у кого нет.

## 3. Концепция и позиционирование

**Оффер:** «Выгрузка заказов и прайс-листов в Excel, CSV, JSON, YML — в файлы и на Яндекс.Диск, Облако Mail.ru, Google Drive. Одно приложение вместо двух. Права — только просмотр. Экспорт включён в цену».

**Порядок выхода:** сразу комбайн (оба модуля), т.к. общий слой доставки делает это выгодным; в маркетинге давим на «2-в-1», «российские облака — первые в маркетплейсе» и «экспорт без доплат».

## 4. Архитектура

Три независимых слоя:
1. **Модули-источники:** «Заказы», «Прайс-лист» (+ P2: отгрузки, розница, счета покупателей) — чтение МойСклад API.
2. **Трансформация:** конструктор полей и порядка, фильтры, режимы (строки/позиции/сводный), генераторы форматов, предпросмотр на клиенте.
3. **Доставка:** единый адаптер каналов. Канал строится один раз и работает для всех модулей — ключевая маржа против конкурентов.

Дополнительно:
- **Кэш последнего результата** — 24 ч хранение последнего файла по профилю для повторной загрузки и предпросмотра.
- **Единый адаптер чат-ботов** — Telegram/MAX без изменений в ядре.

## 5. Объем MVP: приоритеты P0 / P1 / P2

### P0 — релиз 1.0 (в порядке важности)
- **Конструктор выгрузки:** выбор и порядок полей (drag&drop), доп. поля, режимы заказов «один заказ = одна строка» / «с позициями».
- **Форматы:** XLSX, CSV, JSON, YML.
- **Каналы:** Яндекс.Диск, Облако Mail.ru, Google Drive, секретная ссылка, Email.
- **Доверие:** ручной запуск, кнопка «Тест», журнал выполнений, уведомление об ошибке на почту.
- **Расписание:** ручной / ежедневно в время / каждые N часов.
- **Несколько профилей экспорта.**
- **Безопасность:** права только «просмотр», шифрование токенов.
- **Биллинг:** триал 14 дней (сразу Pro), подписки Lite/Pro, апгрейд с зачетом.
- **Telegram:** уведомления об успехе/ошибке задач.

### P1 — паритет + атака на конкурентов
- **Комплекты** (расчет остатков) и **модификации**.
- **Google Таблицы, Telegram (файлы+уведомления), FTP/SFTP, Webhook.**
- **XML.**
- **Пресеты YML** под площадки (Яндекс.Маркет, Avito, drom, Tiu, Юла).
- **Фильтрация по дополнительным полям.**
- **MAX:** полная интеграция (сообщения, файлы до 4 ГБ, клавиатуры, request_contact, Webhook).
- **Живой предпросмотр выгрузки** (УТП против ЖивойОтчёт): после настройки полей/фильтров — интерактивная таблица с группировками и фильтрами на клиенте, без повторных запросов к API МойСклад. Усиливает кнопку «Тест»: «что видишь — то и уедет в файл».
- **Хранение последнего результата 24 ч** — ссылка «скачать снова» в журнале, возврат к отчёту без повторного прогона.
- **PDF-экспорт** (оформленный отчёт для бухгалтерского сегмента).

### P2 — по тяге клиентов
- **Сводный режим экспорта** (ответ ЖивойОтчёту): агрегаты по группировкам (контрагент/день/склад/папка), меры — количество/сумма, в т.ч. по доп. полям. Для аналитиков без постройки BI-вьюера.
- **Новые модули-сущности:** отгрузки, розничные продажи, счета покупателей (адаптер «модуль → трансформация → доставка» делает добавление дешёвым).
- **Liquid-подобные шаблоны/вычисляемые поля.**
- **БД (MySQL/PostgreSQL).**
- **HTML-отчеты.**
- **«Умный» интервал** (адаптивный шаг расписания).
- **Realtime-синк** по вебхуку МойСклад.
- **СберДиск / VK Cloud / MTS Cloud / Yandex Object Storage** (через универсальный S3-адаптер).
- **Поля для Узбекистана.**

## 6. Данные: поля, фильтры, форматы

### 6.1 Модуль «Заказы» (P0)
**Шапка:** UUID, номер, дата, статус, организация, склад, контрагент/покупатель, телефон, email, адрес доставки, сумма, скидка, НДС, валюта, менеджер, комментарий, доп. поля, ссылка в МойСклад.

**Позиции:** товар, артикул, код, штрихкод, количество, цена, сумма, скидка, НДС, единица.

**Фильтры:** организация, склад, статусы (несколько), период (сегодня/вчера/неделя/месяц/диапазон), сумма мин/макс.

*Примечание: YML для заказов — экзотика, не рекламируем.*

### 6.2 Модуль «Прайс-лист» (P0)
**Поля:** UUID, наименование, артикул, код, штрихкод, группа/категория, единица, цены (каждый тип — отдельная колонка), остатки (доступно/остаток/резерв/ожидание), описание, вес/габариты, изображения (ссылки), доп. поля.

**Фильтры:** организация, склады, типы цен, категории, «остаток > 0», цена мин/макс.

**P1:** модификации, комплекты.

### 6.3 Модули P2 (отгрузки / розница / счета)
Структура — аналогично «Заказам» (шапка + позиции), добавляются специфичные поля: для отгрузок — `shippedSum`, для розницы — `retailStore`/`shift`, для счетов — `paymentPlannedMoment`.

### 6.4 Требования к форматам
- **XLSX:** автоширина колонок, оформленная шапка, группировки.
- **CSV:** выбор кодировки (UTF-8 BOM / Windows-1251) и разделителя (`;`, `,`, таб) — под русский Excel.
- **JSON:** массив строк или `{meta, rows}`.
- **YML:** стандарт YML (categories/offers), изображения, vendor — готовность к маркетплейсам.
- **PDF (P1):** оформленный отчёт с заголовком, датой, итогами.
- **XML (P1):** произвольная XML-структура по шаблону.

## 8. Служебная механика

- **Профиль экспорта** = модуль + поля/порядок + фильтры + формат + канал + расписание.
- **Кнопка «Тест»** — прогон без отправки / отправка в тестовый пункт.
- **Журнал:** время, статус, число строк, размер файла, текст ошибки.
- **Уведомления:** Email (P0), Telegram (P1).
- **Права приложения (МойСклад):** просмотр — валюты, склады, товары и услуги, юр. лица, контрагенты, заказы покупателей, доп. поля. Без админ-прав.
- **Предпросмотр (P1):** после сохранения профиля — кнопка «Посмотреть», открывающая интерактивную таблицу по последнему прогону (данные в кэше 24 ч). Группировки и фильтры применяются на клиенте без повторного запроса к API.
- **Кэш последнего результата (P1):** файл последней выгрузки хранится 24 часа на стороне приложения; в журнале — ссылка «скачать снова». Снижает нагрузку на API и даёт UX «вернуться к отчёту» (по аналогии с ЖивойОтчётом).
- **Прозрачность по данным:** в UI показываем список сущностей, к которым обращается профиль; пояснение: «временные файлы удаляются после доставки, ПД не хранятся at rest».

## 10. Технический план

**Порядок работ в P0:**
1. Слой МойСклад API: пагинация, rate-limits, заказы+позиции, товары+остатки+цены — средняя сложность.
2. Слой доставки: адаптер «хранилище» (Яндекс OAuth/REST, Mail.ru WebDAV, Google Drive OAuth, файл-ссылка) — средняя, главный актив продукта.
3. Генераторы форматов — низкая.
4. UI профилей, конструктор, «Тест», журнал — средняя.
5. Планировщик + уведомления — низкая.
6. Биллинг/триал — низкая.

**Безопасность и стабильность:** шифрование OAuth-токенов at rest, refresh/revoke; фоновые воркеры, чанкование больших выгрузок; retry с экспоненной задержкой для дисков.

**P1 — дополнительные работы:**
- Кэш результата (24 ч) на object storage + подписанные URL «скачать снова».
- Предпросмотр-таблица на клиенте (агрегация в браузере по JSON-данным из кэша).
- MAX-интеграция и PDF-генератор.

## 14. Модель развертывания и эксплуатация

### 14.1 Разделение ответственности
- **Маркетплейс МойСклад:** витрина, установка (OAuth), оплата подписки, документы клиенту.
- **Наша сторона:** SaaS на своей инфраструктуре (VPS на этапе 1), обработка данных, поддержка функционала выгрузок.

### 14.2 Интеграция с МойСклад
- **OAuth 2.0:** redirect URI на нашем домене, обмен/refresh токенов, хранение per-client в зашифрованном виде.
- **Проверка статуса подписки** через API маркетплейса перед запуском задач; при отписке — стоп планировщика, очистка токенов после grace-периода.
- **Онбординг:** мастер первого запуска с пресетом профиля и кнопкой «Тест» (цель — первый успешный экспорт в первые 24 ч).
- **Проверить до разработки:** длительность триала (14 vs 7 дней), поддержка нескольких тарифов в одном приложении (Lite/Pro), размер комиссии.

### 14.3 Архитектура на VPS (этап 1)
- **docker-compose:** web (UI+API), worker, scheduler, PostgreSQL, Redis (персистентная очередь), object storage (для P1-кэша результатов).
- **Сквозная обработка:** чтение → генерация → доставка → удаление временного файла; данные и ПД не хранятся at rest (кроме кэша последнего результата с TTL 24 ч).
- **Лимиты конкурентности** воркеров, чанкование, rate-limit к API МойСклад per-client.
- **Бэкапы:** ежедневный зашифрованный дамп БД и конфигураций в Yandex Object Storage; runbook восстановления.
- **Мониторинг:** внешний uptime, Sentry, Telegram-алерты (здоровье сервисов, очередь, упавшие задачи).

**Этап 2 (рост):** управляемые БД/Redis, воркеры на отдельном VPS, временные файлы в object storage.

### 14.4 Безопасность
- Хостинг в российском дата-центре (локализация 152-ФЗ).
- Шифрование токенов at rest (AES-256-GCM), ключ вне БД.
- HTTPS everywhere, SSH-ключи, фаервол, БД/Redis без внешних портов.
- Логи без персональных данных (маскирование).

### 14.5 Экономика
- Стоимость этапа 1: VPS 4–8 ГБ (~1–3 тыс ₽/мес) + object storage; безубыточность — несколько подписок.
- Комиссия маркетплейса закладывается в цену тарифов.

## 15. Чат-боты: Telegram и MAX

**Чат-боты — «всегда включенный» канал доставки выгрузок и уведомлений.**

**MAX — новое УТП** наравне с российскими облаками: первое приложение для МойСклад с ботом в MAX закрывает экосистему VK целиком (Яндекс.Диск + Облако Mail.ru + MAX = полный российский стек).

- **Telegram (P0 — уведомления, P1 — файлы/кнопки):** базовый канал, паритет с конкурентами, но в рамках «2-в-1» и дешевле.
- **MAX (P1, стратегическое УТП):**
  - ни один конкурент не интегрирован с MAX — занимаем нишу первыми;
  - файлы до 4 ГБ (против 50 МБ в Telegram) — большие прайсы с картинками;
  - inline-кнопки: запустить снова / журнал / настройки прямо из чата;
  - `request_contact` с hash-верификацией — безопасная привязка без SMS.

**Архитектурно:** единый адаптер чат-ботов (как адаптер хранилищ) — ядро не знает о конкретном мессенджере; P2-мессенджеры добавляются без переделки.

**Тарифная привязка:**
- Lite — Telegram, уведомления об ошибках;
- Pro — Telegram + MAX полностью (уведомления, файлы, кнопки) — усиливает апселл.

**Go-to-market:** «Чат-бот в MAX — первый в маркетплейсе МойСклад»; MAX как крючок для корпоративных клиентов с политикой импортозамещения.

**Техническая спецификация:** chatbots.md.

## 1. Резюме

**Продукт** — одно расширение-«комбайн» для МойСклад: экспорт заказов покупателей и прайс-листов (товары/цены/остатки) в форматы XLSX, CSV, JSON, YML с доставкой в облачные диски: Яндекс.Диск, Облако Mail.ru, Google Drive, а также файл-ссылка и Email.

**Дифференциаторы** (в порядке силы):
- **Российские облака** — Яндекс.Диск и Облако Mail.ru нет ни у одного конкурента. Импортзамещение, 152-ФЗ (в заказах — персональные данные клиентов), санкционный риск Google.
- **2-в-1** — одно приложение заменяет две подписки конкурентов (2000–2250 ₽/мес суммарно).
- **Экспорт включён в цену** — без доплат до 1 990 ₽ (как у ЖивойОтчёт).
- **Данные на стороне клиента** — файлы лежат в облаке клиента, а не на сервере вендора.
- **Права «только просмотр»** — контраст с админ-правами Склад24.
- **Цена** — Lite 590 ₽ (дешевле любого конкурента), Pro 990 ₽ (дешевле двух чужих подписок).

**Рынок:** 4 релевантных решения конкурентов, 1300+ установок (оценка платящих ~1500), цены 990–1990 ₽/мес. Платежеспособный спрос доказан.

### 6.1 Модуль «Заказы» (P0)
**Шапка:** UUID, номер, дата, статус, организация, склад, контрагент/покупатель, телефон, email, адрес доставки, сумма, скидка, НДС, валюта, менеджер, комментарий, доп. поля, ссылка в МойСклад.

**Позиции:** товар, артикул, код, штрихкод, количество, цена, сумма, скидка, НДС, единица.

**Фильтры:** организация, склад, статусы (несколько), период (сегодня/вчера/неделя/месяц/диапазон), сумма мин/макс.

*Примечание: YML для заказов — экзотика, не рекламируем.*

### 6.2 Модуль «Прайс-лист» (P0)
**Поля:** UUID, наименование, артикул, код, штрихкод, группа/категория, единица, цены (каждый тип — отдельная колонка), остатки (доступно/остаток/резерв/ожидание), описание, вес/габариты, изображения (ссылки), доп. поля.

**Фильтры:** организация, склады, типы цен, категории, «остаток > 0», цена мин/макс.

**P1:** модификации, комплекты.

### 6.3 Модули P2 (отгрузки / розница / счета)
Структура — аналогично «Заказам» (шапка + позиции), добавляются специфичные поля: для отгрузок — `shippedSum`, для розницы — `retailStore`/`shift`, для счетов — `paymentPlannedMoment`.

### 6.4 Требования к форматам
- **XLSX:** автоширина колонок, оформленная шапка, группировки.
- **CSV:** выбор кодировки (UTF-8 BOM / Windows-1251) и разделителя (`;`, `,`, таб) — под русский Excel.
- **JSON:** массив строк или `{meta, rows}`.
- **YML:** стандарт YML (categories/offers), изображения, vendor — готовность к маркетплейсам.
- **PDF (P1):** оформленный отчёт с заголовком, датой, итогами.
- **XML (P1):** произвольная XML-структура по шаблону.

## 8. Служебная механика

- **Профиль экспорта** = модуль + поля/порядок + фильтры + формат + канал + расписание.
- **Кнопка «Тест»** — прогон без отправки / отправка в тестовый пункт.
- **Журнал:** время, статус, число строк, размер файла, текст ошибки.
- **Уведомления:** Email (P0), Telegram (P1).
- **Права приложения (МойСклад):** просмотр — валюты, склады, товары и услуги, юр. лица, контрагенты, заказы покупателей, доп. поля. Без админ-прав.
- **Предпросмотр (P1):** после сохранения профиля — кнопка «Посмотреть», открывающая интерактивную таблицу по последнему прогону (данные в кэше 24 ч). Группировки и фильтры применяются на клиенте без повторного запроса к API.
- **Кэш последнего результата (P1):** файл последней выгрузки хранится 24 часа на стороне приложения; в журнале — ссылка «скачать снова». Снижает нагрузку на API и даёт UX «вернуться к отчёту» (по аналогии с ЖивойОтчётом).
- **Прозрачность по данным:** в UI показываем список сущностей, к которым обращается профиль; пояснение: «временные файлы удаляются после доставки, ПД не хранятся at rest».

## 10. Технический план

**Порядок работ в P0:**
1. Слой МойСклад API: пагинация, rate-limits, заказы+позиции, товары+остатки+цены — средняя сложность.
2. Слой доставки: адаптер «хранилище» (Яндекс OAuth/REST, Mail.ru WebDAV, Google Drive OAuth, файл-ссылка) — средняя, главный актив продукта.
3. Генераторы форматов — низкая.
4. UI профилей, конструктор, «Тест», журнал — средняя.
5. Планировщик + уведомления — низкая.
6. Биллинг/триал — низкая.

**Безопасность и стабильность:** шифрование OAuth-токенов at rest, refresh/revoke; фоновые воркеры, чанкование больших выгрузок; retry с экспоненной задержкой для дисков.

**P1 — дополнительные работы:**
- Кэш результата (24 ч) на object storage + подписанные URL «скачать снова».
- Предпросмотр-таблица на клиенте (агрегация в браузере по JSON-данным из кэша).
- MAX-интеграция и PDF-генератор.

## 14. Модель развертывания и эксплуатация

### 14.1 Разделение ответственности
- **Маркетплейс МойСклад:** витрина, установка (OAuth), оплата подписки, документы клиенту.
- **Наша сторона:** SaaS на своей инфраструктуре (VPS на этапе 1), обработка данных, поддержка функционала выгрузок.

### 14.2 Интеграция с МойСклад
- **OAuth 2.0:** redirect URI на нашем домене, обмен/refresh токенов, хранение per-client в зашифрованном виде.
- **Проверка статуса подписки** через API маркетплейса перед запуском задач; при отписке — стоп планировщика, очистка токенов после grace-периода.
- **Онбординг:** мастер первого запуска с пресетом профиля и кнопкой «Тест» (цель — первый успешный экспорт в первые 24 ч).
- **Проверить до разработки:** длительность триала (14 vs 7 дней), поддержка нескольких тарифов в одном приложении (Lite/Pro), размер комиссии.

### 14.3 Архитектура на VPS (этап 1)
- **docker-compose:** web (UI+API), worker, scheduler, PostgreSQL, Redis (персистентная очередь), object storage (для P1-кэша результатов).
- **Сквозная обработка:** чтение → генерация → доставка → удаление временного файла; данные и ПД не хранятся at rest (кроме кэша последнего результата с TTL 24 ч).
- **Лимиты конкурентности** воркеров, чанкование, rate-limit к API МойСклад per-client.
- **Бэкапы:** ежедневный зашифрованный дамп БД и конфигураций в Yandex Object Storage; runbook восстановления.
- **Мониторинг:** внешний uptime, Sentry, Telegram-алерты (здоровье сервисов, очередь, упавшие задачи).

**Этап 2 (рост):** управляемые БД/Redis, воркеры на отдельном VPS, временные файлы в object storage.

### 14.4 Безопасность
- Хостинг в российском дата-центре (локализация 152-ФЗ).
- Шифрование токенов at rest (AES-256-GCM), ключ вне БД.
- HTTPS everywhere, SSH-ключи, фаервол, БД/Redis без внешних портов.
- Логи без персональных данных (маскирование).

### 14.5 Экономика
- Стоимость этапа 1: VPS 4–8 ГБ (~1–3 тыс ₽/мес) + object storage; безубыточность — несколько подписок.
- Комиссия маркетплейса закладывается в цену тарифов.

## 15. Чат-боты: Telegram и MAX

**Чат-боты — «всегда включенный» канал доставки выгрузок и уведомлений.**

**MAX — новое УТП** наравне с российскими облаками: первое приложение для МойСклад с ботом в MAX закрывает экосистему VK целиком (Яндекс.Диск + Облако Mail.ru + MAX = полный российский стек).

- **Telegram (P0 — уведомления, P1 — файлы/кнопки):** базовый канал, паритет с конкурентами, но в рамках «2-в-1» и дешевле.
- **MAX (P1, стратегическое УТП):**
  - ни один конкурент не интегрирован с MAX — занимаем нишу первыми;
  - файлы до 4 ГБ (против 50 МБ в Telegram) — большие прайсы с картинками;
  - inline-кнопки: запустить снова / журнал / настройки прямо из чата;
  - `request_contact` с hash-верификацией — безопасная привязка без SMS.

**Архитектурно:** единый адаптер чат-ботов (как адаптер хранилищ) — ядро не знает о конкретном мессенджере; P2-мессенджеры добавляются без переделки.

**Тарифная привязка:**
- Lite — Telegram, уведомления об ошибках;
- Pro — Telegram + MAX полностью (уведомления, файлы, кнопки) — усиливает апселл.

**Go-to-market:** «Чат-бот в MAX — первый в маркетплейсе МойСклад»; MAX как крючок для корпоративных клиентов с политикой импортозамещения.

**Техническая спецификация:** chatbots.md.
